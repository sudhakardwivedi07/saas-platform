CLIENT LIMIT ENFORCEMENT (Clients Page) + AUTOCOMPLETE FIX
Project: SaaS Platform

OVERVIEW
--------
Two independent fixes were applied to the Client Management page (/clients):

  Fix 1 — Max Clients enforcement on the Clients page
    When an Admin tries to add a new client via the "+ Add Client" button,
    the system now checks whether the firm's active plan allows any more
    clients (based on the plan's "Max Clients" / max_users value).
    If the limit has been reached, the user sees a SweetAlert warning
    immediately — before they even open the form.  A server-side guard is
    also in place so the limit cannot be bypassed by a direct POST.

  Fix 2 — Autocomplete on email/password fields in the Add Client modal
    The browser was auto-filling the Email and Password fields in the
    "Add New Client" popup with the logged-in admin's saved credentials.
    This was confusing and incorrect.  The fields are now always blank
    when the modal opens.

================================================================================
FIX 1 — MAX CLIENTS ENFORCEMENT (Clients Page)
================================================================================

Background
----------
The plan's "Max Clients" field is stored as max_users on both the Package
(SuperAdmin plan) and ClientPackage (admin-defined plan) tables.
Company::activePlan() returns the active plan regardless of which type it is.

The same limit was previously enforced in TenantUserController (Users page).
This fix brings the same enforcement to the Clients page (ClientController).

How the limit is counted
------------------------
Each "Add Client" operation creates one sub-company (created_by = admin's
company_id).  The count of those sub-companies equals the number of clients.

  $currentClientCount = Company::withoutGlobalScopes()
      ->where('created_by', $parentCompanyId)
      ->count();

This is compared against $plan->max_users.

USER EXPERIENCE
---------------
Case A — Limit NOT reached:
  Button shows normally.  Clicking opens the Add Client modal.

Case B — Limit IS reached (frontend guard):
  Clicking "+ Add Client" triggers a SweetAlert immediately:
    Title:  "Client Limit Reached"
    Text:   "You have reached the maximum of N client(s) allowed on your
             current plan. Please upgrade your plan to add more clients."
  The modal never opens, so the user doesn't waste time filling the form.

Case C — Server-side guard (safety net):
  If the frontend guard is bypassed (e.g. direct POST), the store() method
  also checks the limit and redirects to clients.index with:
    session('error') = "Maximum client limit reached. Please upgrade your
                        plan to add more clients."
  The existing SweetAlert handler in layouts/app.blade.php picks this up and
  shows the error popup automatically.

FIX 2 — AUTOCOMPLETE ON EMAIL / PASSWORD FIELDS
================================================================================

Root cause
----------
Browsers detect any form that contains an <input type="email"> or
<input type="password"> as a potential login form and pre-fill both fields
with the user's saved credentials.  The Add Client modal matched this
pattern, causing the admin's own email and password to be inserted into the
new client's fields as soon as the modal opened.

Solution
--------
Three layers of protection were applied:

  Layer 1 — HTML attribute on email input:
    autocomplete="off"
    This hints to most browsers not to autofill this specific field.

  Layer 2 — HTML attribute on password input:
    autocomplete="new-password"
    This tells browsers explicitly that this is a NEW password being created,
    not a login password to fill from saved credentials.  Chrome, Firefox,
    and Edge all respect this attribute.

  Layer 3 — JavaScript: openAddClientModal() function
    Programmatically clears both fields every time the modal opens, and then
    focuses the "Full Name" field (a non-credential field) so the browser has
    no reason to trigger autofill behaviour:

      function openAddClientModal() {
          document.getElementById('ac-email').value    = '';
          document.getElementById('ac-password').value = '';
          document.getElementById('modal-add-client').classList.add('open');
          setTimeout(function() {
              document.querySelector('#modal-add-client input[name="name"]')
                  .focus();
          }, 80);
      }
