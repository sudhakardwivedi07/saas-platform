================================================================================
CUSTOM LOGIN PAGE FEATURE
Project: SaaS Platform
Date:    2026-05-08
================================================================================

OVERVIEW
--------
Each firm (admin company) now has a fully customisable login page.  When a
client or team member navigates to the firm's domain or subdomain, they see
the firm's branded login page instead of a generic one.

The admin can customise the login page from Settings → Login Page:
  • Heading text
  • Subheading text
  • Background type: gradient, solid colour, or custom image
  • Background colour(s) (start + end for gradient; one colour for solid)
  • Card background colour
  • Sign-In button colour
  • Logo (same logo used in the sidebar — shared with Branding)
  • Background image (only uploaded/shown when bg type = image)

A live preview on the right-hand side of the form updates instantly as the
admin changes any setting.

================================================================================
HOW IT WORKS — ROUTING TO THE CORRECT LOGIN PAGE
================================================================================

The existing IdentifyTenant middleware (app/Http/Middleware/IdentifyTenant.php)
already resolves the current tenant (Company) from:
  1. A matching custom_domain column on the companies table
  2. The first subdomain segment of the request host

Once a tenant is identified, the company() helper and the branding()
relationship provide the firm's CompanyBranding record to every view.

AuthController::showLogin() already passes:
  $branding = company()?->branding;

to the login view.  The view (resources/views/auth/login.blade.php) uses
that $branding record to apply all customisations at render time.

Result: every firm's login URL automatically shows its own branded page with
zero extra routing logic.
