ROLE RENAME: client_admin → admin  |  user → client
Project: SaaS Platform
Date:    2026-05-08
================================================================================

OVERVIEW
--------
Two role renames were applied across the entire project:

  1. 'client_admin'  →  'admin'
     The role assigned to the firm administrator created by the Super Admin
     when onboarding a new firm is now named 'admin' instead of 'client_admin'.

  2. 'user'  →  'client'
     A new 'client' role was created with identical permissions to the
     previous 'user' role.  All existing users who held the 'user' role
     have been migrated to 'client'.  The old 'user' role has been deleted.

================================================================================
WHY THESE CHANGES WERE MADE
================================================================================

  client_admin → admin
    The old name was redundant.  Every administrator in the tenant panel is
    already scoped to their own firm, so the 'client_' prefix added no
    information and made role-check code verbose.  'admin' is shorter,
    clearer, and consistent with common SaaS conventions.

  user → client
    Users created by an admin inside a firm represent that firm's end-clients.
    The generic name 'user' was ambiguous — every person in the system is a
    user.  'client' precisely describes what this role represents: a client
    of the firm.

================================================================================
DATABASE CHANGES
================================================================================

Migration file:
  database/migrations/2026_05_08_000001_rename_client_admin_to_admin_and_add_client_role.php

What the migration does (up):
  1. UPDATE roles SET name='admin'  WHERE name='client_admin'
  2. UPDATE user_companies SET role='admin'  WHERE role='client_admin'
     (pivot table that tracks which admin manages which sub-company)
  3. INSERT new role 'client' (guard_name='web')
  4. Copy all permission rows from role_has_permissions for 'user' → 'client'
  5. UPDATE model_has_roles: reassign all 'user'-role users to 'client'
  6. DELETE the old 'user' role (permissions + role row)
  7. Clear Spatie permission cache

What the migration does (down — rollback):
  1. Rename 'admin' back to 'client_admin'
  2. Revert user_companies pivot back to 'client_admin'
  3. Rename 'client' back to 'user'
     (permissions stay attached; model_has_roles stays as-is)

Run migration:    php artisan migrate
Rollback:         php artisan migrate:rollback
